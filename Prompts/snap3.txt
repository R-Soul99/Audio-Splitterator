==================================================
THE INTENDED USER WORKFLOW
==================================================

The intended workflow is:

1. Select a representative quiet/noise-floor section of the recording.
2. Press Detect.
3. Detect establishes the audio level that represents "quiet".
4. Move/hover the waveform cursor around the recording.
5. As the cursor approaches audio at or below that detected quiet threshold:
   - the cursor should acquire that quiet area
   - the radar/snap visual should ping
6. If the user places a marker while a quiet target is acquired:
   - place it at the sensible quiet location

In other words:

SNAP IS A LIVE QUIET-AUDIO RADAR.

It should NOT depend solely on previously generated Auto-Split candidates.

==================================================
CURRENT PROBLEM
==================================================

The current implementation appears to use valid Auto-Split quiet regions/candidates as the source of Snap targets.

Even after changing capture from candidate-centre to whole-region + ±Snap, it is still very difficult to trigger.

A simple test demonstrates the mismatch:

- play a record
- lift the needle several times to create very obvious silent sections
- select one needle-lift section
- press Detect
- move the cursor over/near the other needle-lift sections
- even with Snap turned high, they are not reliably acquired/pinged

Those should be extremely easy targets.

==================================================
IMPORTANT SEPARATION
==================================================

Please separate these two concepts:

AUTO SPLIT
----------
Uses:
- Noise Floor
- Gap
- vinyl interruption tolerance
- contiguous quiet-region logic

Gap means:
"How long must quiet audio last before an automatic split is proposed?"

MANUAL SNAP / RADAR
-------------------
Uses:
- detected Noise Floor
- Snap search radius

It should NOT require the quiet area to satisfy the Auto-Split Gap duration.

A quiet section may be too short to qualify for Auto Split but should still be discoverable manually.

This distinction is important.

==================================================
LIVE HOVER ANALYSIS
==================================================

While the pointer/cursor moves over the waveform in the relevant marker-placement context:

analyse/search the audio around the cursor position.

Using the shared stereo RMS data where practical:

- search within ±Snap distance
- find audio windows at or below the current Noise Floor threshold
- use the louder stereo channel, consistent with Detect
- find the nearest sensible quiet target

Do not require that target to already exist in the Auto-Split candidate list.

==================================================
WHAT SNAP KNOB SHOULD MEAN
==================================================

Snap should mean:

"How far around the cursor should I search for qualifying quiet audio?"

Example:

Snap = 150 ms

Search approximately:

cursorTime - 150 ms
through
cursorTime + 150 ms

If qualifying quiet audio exists in that search window:
- acquire it

If none exists:
- no snap target

Turning Snap higher should therefore make the radar progressively easier to trigger.

==================================================
TARGET SELECTION
==================================================

When qualifying quiet samples/windows are found inside the Snap radius:

Do not snap randomly to the first low sample.

Prefer a stable sensible location.

For example:

1. group adjacent below-threshold windows into local quiet runs
2. choose the nearest quiet run to the cursor
3. choose either:
   - the quietest point/window within that run
   - or a stable central point within it

The result should not jitter constantly as the pointer moves by one pixel.

==================================================
RADAR PING ON HOVER
==================================================

A marker click should NOT be required to trigger the visual feedback.

When cursor movement acquires a valid quiet target:

- trigger the existing radar/phosphor vertical-line ping
- leave the temporary fading trace at the acquired location

This is the user's visual confirmation:

"Yes — the detector sees silence here."

Avoid firing a new ping every animation frame while remaining over the same target.

Suggested behaviour:

- ping when a quiet target is newly acquired
- do not ping repeatedly while still locked to essentially the same target
- allow another ping after leaving and re-entering, or acquiring a different target

If the current interaction already moves the cursor during Snap and that is intentional, preserve it.

The critical requirement is that QUIET ACQUISITION happens during hover, not only during marker placement.
